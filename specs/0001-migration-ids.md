# 0001 — Возрастающие id миграций

**Статус:** done (оформлено задним числом — код уже был реализован до того, как завели этот файл)

## Контекст

`TODO.md`, пункт 1: "id миграций должен быть только возрастающим". По умолчанию Alembic генерирует
случайный hex revision id (например `b42b7155ba9f`) при каждом `alembic revision`. Такой id не
показывает порядок создания миграций и не сортируется лексикографически по времени — сложно на глаз
понять историю изменений схемы.

## Решение

Revision id — простой возрастающий счётчик с ведущими нулями: `0001`, `0002`, `0003`, ... Формат выбран
вместо UTC-таймстампа осознанно: короче, читается как номер версии, для однопользовательского проекта
риск конфликтов id при параллельной разработке в разных ветках не является проблемой.

Единственный способ создать новую миграцию — `scripts/new_migration.sh "<message>"`. Прямой вызов
`alembic revision` в обход скрипта не запрещён технически, но не поддерживается: он оставит id на
усмотрение Alembic и нарушит конвенцию.

## Критерии приёмки

1. Вычисление следующего id — чистая функция от списка существующих файлов миграций (не зависит от
   alembic/БД), покрыта тестом: пустая директория → `0001`; при существующих `0001`, `0003` — следующий
   `0004` (по максимуму, а не по количеству файлов).
2. `scripts/new_migration.sh` использует эту функцию для вычисления id перед вызовом
   `alembic revision --autogenerate --rev-id=<id>`.
3. Существующая миграция схемы (`alembic/versions/0001_initial_schema.py`) имеет `revision = '0001'`.
4. Реальная БД (`tracker.db`) застемплена на `0001` (`alembic current` показывает `0001 (head)`).

## Реализация

- `scripts/migration_ids.py` — функция `next_migration_id()`, тестируемая независимо от Alembic
- `scripts/new_migration.sh` — вызывает `migration_ids.py`, затем `alembic revision --autogenerate`
- `tests/test_migration_ids.py` — автоматическая проверка критерия приёмки №1 (взамен разовой ручной
  проверки, которая ничего не оставляет после себя), помечена `@pytest.mark.spec("0001")`

## Конвенция: тесты на критерии приёмки

Тесты, проверяющие критерии приёмки конкретной спеки, лежат в общей `tests/` (не в отдельной папке —
искали баланс между трассируемостью и лишней инфраструктурой) и помечаются
`@pytest.mark.spec("<id спеки>")`. Запустить все приёмочные тесты: `pytest -m spec`. pytest не умеет
фильтровать по аргументу маркера (`-m 'spec("0001")'` — синтаксическая ошибка), поэтому тесты на
конкретную спеку запускаются по имени файла: `pytest tests/test_migration_ids.py`.
- `alembic/versions/0001_initial_schema.py` — переименована из `b42b7155ba9f_initial_schema.py`
