# 0008 — Drag'n'drop + выравнивание для «Базы знаний»

**Статус:** done

**Примечание (задним числом):** после первой реализации выравнивание работало некорректно, когда
`.topics-grid` уже сама была уже родителя (из-за `max-width`, выставленного `fitTopicsWidth()`):
`justify-content` двигал карточки только внутри самой сетки, а сама сетка как блочный элемент
оставалась прижата влево внутри секции, из-за чего при `align-right`/`align-center` правый/центр
край карточек не совпадал с правым краем остального контента страницы. Исправлено добавлением
`margin-right/left: auto` на `.topics-grid.align-left/center/right` — теперь позиционируется и сама
сетка, а не только её содержимое.

**Примечание 2 (задним числом):** фиксированная ширина карточки (`flex: 0 0 300px`) иногда оставляла
в строке 3 карточки при заметном свободном месте, куда почти влезала 4-я. Заменено на эластичную
`flex: 1 1 260px; max-width: 340px` — браузер сам решает, сколько карточек ставить в ряд (3 или 4), и
растягивает их без остатка. Ручной JS-расчёт `fitTopicsWidth()`/`TOPIC_CARD_WIDTH` больше не нужен и
удалён — `margin-right/left: auto` из примечания 1 тоже убраны, так как сетка теперь всегда занимает
полную ширину родителя и `justify-content` сам корректно позиционирует неполные строки.

**Примечание 3 (задним числом):** по решению пользователя эластичность карточки убрана обратно —
строка должна вмещать ровно 3 темы и не больше, вместо динамического подбора 3 или 4. Промежуточный
вариант с фиксированной шириной 360px не подошёл: три карточки по 360px не заполняли всю доступную
ширину контейнера (1112px из ~1184px), из-за чего даже полная строка не доставала до правого края
при `align-left`. Финальное решение — `flex: 0 0 calc((100% - 32px) / 3)` (32px = сумма двух
зазоров по 16px): ширина карточки высчитывается так, что ровно 3 карточки всегда заполняют 100%
ширины контейнера без остатка, а 4-я никогда не помещается в строку. Пустое место остаётся только в
действительно неполных строках (меньше 3 тем) — там работает переключатель выравнивания.

## Контекст

После TRACKER-2 (блоки → темы → понятия) осталось два запроса:

1. **Асимметрия сетки тем.** `.topics-grid` на CSS Grid (`auto-fit`/`minmax`) — незаполненная
   последняя строка блока всегда прижата влево без вариантов выравнивания. Та же проблема, что раньше
   решалась для доски задач (`fitBoardWidth()` + `.board.align-*`), чинится тем же приёмом.
2. **Drag'n'drop**, по аналогии с доской, но на три уровня: блоки — между собой (как колонки-статусы),
   темы — между блоками (как задачи между колонками), и дополнительно понятия — между темами (третий
   уровень, специфичный для базы знаний). Все перемещения — "в конец целевого списка", без точного
   позиционирования внутри — так же, как задачи между колонками на доске.
3. **Выравнивание** — один глобальный переключатель на всю страницу, как на доске.

## Критерии приёмки

1. `PUT /api/blocks/reorder` — принимает `{keys: [id, ...]}`, проверяет полное совпадение с
   существующими id блоков (иначе 400), проставляет `position` по порядку (по образцу
   `PUT /api/statuses/reorder`).
2. `PATCH /api/concepts/{id}` — принимает необязательный `topic_id`; если передан и отличается от
   текущего: 404, если целевой темы нет; иначе переносит понятие в целевую тему с
   `position = max(position) + 1` среди понятий этой темы.
3. На странице «База знаний» — глобальный переключатель выравнивания (лево/центр/право), как на
   доске, применяется ко всем сеткам тем сразу; неполная последняя строка карточек реагирует на
   переключатель.
4. Блоки можно перетаскивать между собой для изменения порядка.
5. Темы можно перетаскивать в другой блок (включая секцию «без блока») — всегда добавляются в конец
   списка целевого блока.
6. Понятия можно перетаскивать в другую тему — всегда добавляются в конец списка понятий целевой
   темы.

## Осознанно не делаем

- Точное позиционирование при перетаскивании (вставка "между" элементами) — везде только "в конец
  списка", как уже работает на доске для задач.
- Отдельное выравнивание на блок — один глобальный переключатель на всю страницу.
- Автотесты на сам drag'n'drop и выравнивание (JS, без тестовой инфраструктуры на фронте) —
  проверяется вручную через запуск приложения и скриншоты.
