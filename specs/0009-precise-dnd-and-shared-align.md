# 0009 — Точечный drag'n'drop + единый виджет выравнивания

**Статус:** done

## Контекст

Два независимых запроса от пользователя:

1. Сейчас перетаскивание темы/понятия всегда добавляет элемент в конец целевого списка (spec 0008).
   Нужна точная вставка "между" двумя соседними элементами — только для тем (внутри блока и между
   блоками) и понятий (внутри темы и между темами). Блоки по-прежнему переставляются только целиком
   (как решили в 0008) — на это точечность не распространяется.
2. Переключатель выравнивания сейчас продублирован — свой в шапке доски и свой в шапке базы знаний.
   Нужен один общий виджет-контрол на всё приложение, а не по одному на страницу.

## Решения

- Точечный drag'n'drop — только темы и понятия, блоки остаются "целиком".
- Один физический виджет выравнивания в общей шапке (над вкладками «Доска»/«База знаний»), но
  значения выравнивания для доски и базы знаний остаются раздельными (разные `localStorage`-ключи) —
  меняется расположение контрола в разметке, а не его семантика по страницам.

## Критерии приёмки

### Точечный drag'n'drop

1. `PATCH /api/topics/{id}` принимает необязательный `position: int`. Если передан — тема
   вставляется в список тем целевого блока (`block_id`, если тоже передан, иначе текущий) на этот
   индекс, позиции остальных тем в этом списке сдвигаются соответственно. Если `position` не передан
   и `block_id` меняется — прежнее поведение (добавление в конец).
2. `PATCH /api/concepts/{id}` — аналогично, `position` работает относительно списка понятий целевой
   темы (`topic_id`).
3. Перетаскивание темы на другую тему-карточку (а не в пустую область блока) вставляет её перед/после
   этой карточки в зависимости от того, на какую половину карточки (левую/правую) произошёл дроп.
4. Перетаскивание понятия на другое понятие вставляет его перед/после этого понятия в зависимости от
   того, на какую половину строки (верх/низ) произошёл дроп.
5. Перетаскивание на пустую область блока (не на карточку) — прежнее поведение, добавление в конец
   (как в 0008).

### Единый виджет выравнивания

6. В разметке ровно один `.align-control` — в общей шапке над вкладками «Доска»/«База знаний»,
   видимый на обеих страницах (скрыт только на странице деталей задачи, где нечего выравнивать).
7. Активная кнопка контрола отражает выравнивание текущей страницы (доски или базы знаний) и
   переключается при смене вкладки. Значения выравнивания по-прежнему хранятся раздельно
   (`boardAlign`/`knowledgeAlign` в `localStorage`).

## Осознанно не делаем

- Точное перетаскивание блоков (вставка между конкретными блоками, а не куда попало) — блоки
  по-прежнему переставляются перетаскиванием на другой блок целиком, без промежуточной позиции.
- Общее (единое) значение выравнивания для доски и базы знаний — они остаются независимыми
  настройками, меняется только расположение переключателя в разметке.
- Автотесты на сам drag'n'drop (JS) и на объединение шапки (вёрстка) — только на новую позиционную
  логику бэкенда. Проверяется вручную через запуск приложения и скриншоты, как и весь остальной JS в
  проекте.

## Реализация

- `app/schemas.py` — `TopicUpdate.position`, `ConceptUpdate.position`
- `app/logic.py` — `reposition_in_parent(conn, table, parent_col, item_id, parent_value, index) ->
  int`: общий алгоритм вставки-со-сдвигом, переиспользуется для тем (`parent_col=block_id`) и понятий
  (`parent_col=topic_id`)
- `app/api.py` — `update_topic`/`update_concept` используют `reposition_in_parent`, когда передан
  `position`
- `static/app.js` — `onTopicDragOver`/`onTopicDrop` на `topic-card` дополнены определением
  левой/правой половины при перетаскивании темы (не только понятия); аналогично для `concept-row` —
  верх/низ при перетаскивании понятия; визуальные классы-индикаторы вставки
- `static/index.html` — единая общая шапка (заголовок, вкладки, `.align-control`) вместо дублирования
  в `#board-view`/`#knowledge-view`; специфичные для страницы кнопки действий остаются в своих секциях
- `static/app.js` — `getBoardAlign/applyBoardAlign/setBoardAlign` и
  `getKnowledgeAlign/applyKnowledgeAlign/setKnowledgeAlign` заменяются на общие `getAlign/applyAlign/
  setAlign`, определяющие целевую страницу по текущему роуту

## Тесты (TDD, `@pytest.mark.spec("0009")`)

`tests/test_knowledge_api.py`:
- вставка темы по `position` внутри одного блока — сдвиг позиций соседей, полная проверка строк в БД
- вставка темы по `position` при одновременном переносе в другой блок
- вставка понятия по `position` внутри одной темы и при переносе в другую тему
- `position`, выходящий за границы списка (отрицательный / больше длины) — не падает, вставляет в
  ближайший край (0 или конец)
