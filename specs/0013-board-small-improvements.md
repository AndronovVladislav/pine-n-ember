# 0013 — Доска: переименование статусов, дефолтный статус, лимит карточек в статусе

**Статус:** done

## Контекст

TRACKER-8 (из БД приложения) — три маленькие, независимые доработки доски, объединённые в один
тикет вместо трёх отдельных спек (каждая по отдельности слишком мала для полноценного SDD-цикла):

1. Переименование статусов — сейчас можно удалить статус, но не переименовать.
2. Дефолтный статус при создании карточки — был помечен «возможно надо погруммить».
3. Столбец должен показывать примерно 4 карточки, дальше — прокрутка, а не растягивание колонки на
   всю высоту доски.

## Груминг: дефолтный статус

Проверено: `SqlAlchemyBoardRepository._resolve_status` уже берёт первый статус по `position`, если
статус не передан при создании карточки (`app/domains/board/repository.py`). Это и есть дефолтный
статус — явный флаг «дефолтности» не нужен (пользователь подтвердил: первый по порядку — ожидаемое
поведение). **По этому пункту код не меняется**, документируем как уже реализованный.

## Критерии приёмки

1. `PATCH /api/statuses/{key}` — новый роут, переименовывает статус (обновляет `label`, `key` не
   меняется — на него уже могут ссылаться задачи по `status_key`). 404 (`NotFound`), если статуса с
   таким `key` нет. Пустой/пробельный `label` — 400 (`InvalidOperation`), по аналогии с валидацией
   остальных `label`-полей в проекте.
2. На доске у заголовка колонки — клик по названию статуса открывает инлайн-редактирование (текстовое
   поле на месте `.column-title`, без модалки — единообразно с остальным UI доски/финансов в этом
   проекте). `Enter`/потеря фокуса сохраняет (`PATCH`), `Escape` отменяет правку без запроса.
3. Колонка ограничена по высоте: не более ~4 карточек видно без скролла, дальше — вертикальная
   прокрутка внутри `.cards`, шапка колонки (`.column-head`) остаётся видимой и не скроллится.
   Значение высоты — не с потолка: посчитано на реальных данных (`GET /api/board`, medians ниже).
4. Существующий HTTP-контракт (board/knowledge/finance) не меняется, кроме нового роута из п.1 — весь
   набор тестов (59) проходит без правки существующих ассертов.

## Расчёт высоты колонки (для п.3)

По текущим данным доски: медианная длина заголовка карточки — 18 символов, при ширине колонки 240px
(минус паддинги — рабочая ширина текста ~212px) и шрифте 13.5px это укладывается в одну строку
(на глаз ~31 символ/строку у Outfit 500 на этом кегле) — то есть медианная карточка однострочная.
Высота такой карточки (по `static/style.css`): паддинг 12+12=24px + заголовок (line-height 1.4×13.5≈19px)
+ отступ под заголовком 8px + строка метаданных (тег/дата, ~18px) + границы 2px ≈ **71px**.
4 карточки + 3 зазора по 8px (текущий `.cards { gap: 8px }`) = 4×71 + 3×8 = 284 + 24 = **308px**.
Берём `max-height: 308px` на `.cards` с `overflow-y: auto`.

## Осознанно не делаем

- Настраиваемое количество видимых карточек (4 — раз и навсегда, не параметр настроек) — совпадает
  с духом остального проекта (нет настраиваемых лимитов там, где хватает константы, см. finance
  `recent_operations`).
- Явный флаг «дефолтный статус» в БД — первый по `position` и так однозначно определяет дефолт (см.
  груминг выше); строка неоднозначна ровно до тех пор, пока в доске остался хотя бы один статус, а
  без единого статуса создание карточки и так упирается в другие сценарии, не в выбор дефолта.
- Переименование `key` статуса вместе с `label` — `key` используется как внешний ключ в `tasks`,
  трогать его при рефакторинге не нужно (аналогично тому, что `id` задач/тем никогда не меняется от
  правки заголовка).

## Реализация

- `app/domains/board/ports.py` — новый метод `rename_status(status_key: str, label: str) -> Status`.
- `app/domains/board/repository.py` — `SqlAlchemyBoardRepository.rename_status`: находит статус по
  `key` (`NotFound`), валидирует непустой `label` (`InvalidOperation`), обновляет строку.
- `app/api/board.py` — `PATCH /statuses/{status_key}`, `@handle_domain_errors`, тело — новая
  Pydantic-схема `StatusRename` (`label: str`) в `app/schemas.py`.
- `static/index.html`/`static/app.js` — инлайн-редактирование `.column-title` (по образцу того, как
  уже сделаны инлайн-правки в других местах приложения, без модалок).
- `static/style.css` — `.cards { max-height: 308px; overflow-y: auto; }`.

## Тесты

`tests/api/test_board.py` — новые сценарии: успешное переименование статуса, 404 на несуществующий
`key`, 400 на пустой `label`, существующие задачи внутри переименованного статуса не теряют связь
(`status` в ответе задачи не меняется, только `label` у статуса).
