# 0014 — Доска: очереди вместо тегов, ключ карточки вместо дедлайна

**Статус:** done

## Контекст

TRACKER-6 (из БД приложения). Часть исходного пункта TODO разбита так: TRACKER-8 (мелкие правки
доски) уже сделан отдельно (`specs/0013-board-small-improvements.md`); этот тикет — сама доменная
замена «тег → очередь» и убор дедлайна с карточки.

## Груминг (зафиксировано в диалоге)

1. «Очередь» — не более строгая сущность, чем тег сейчас: та же модель (одна метка на карточку,
   создаётся на лету прямо в поле карточки, без отдельного экрана управления). Меняется терминология
   и то, как это называется в коде/API/UI, поведение — нет.
2. Дедлайн (`due`) убирается полностью — не прячется в UI, а перестаёт существовать как поле.
3. Вместо дедлайна на карточке показывается короткий ключ карточки — префикс + порядковый номер
   (`TASK-1`, `TASK-2`, ...), в том же моноширинном стиле, в котором сейчас пишется дедлайн.
   Номер — сквозной автоинкремент на уровне БД (nativeSERIAL), не генерируется в коде: не нужно
   вручную разруливать конкурентный doступ, как пришлось бы с ручным counter+INSERT.

## Критерии приёмки

1. Домен `app/domains/board/` — сущность `Tag` переименована в `Queue` везде: модель
   `models/tag.py` → `models/queue.py` (таблица `tags` → `queues`), dto `Tag` → `Queue`,
   `_resolve_tag` → `_resolve_queue`, `tag_key` → `queue_key` (FK), `getTag`/`TAGS`/`.tag` в
   `static/app.js`/`style.css` → `getQueue`/`QUEUES`/`.queue`. Поведение резолвинга (найти по
   `label`/`slug`, иначе создать новую с следующим цветом палитры) не меняется, только имена.
2. `Task.due` убрано из модели, dto, схем, API-контракта и фронтенда полностью — ни одно поле с
   именем `due`/«дедлайн»/«дата» в контексте карточки доски больше не существует.
3. У `Task` — новое поле `number: int`, генерируется БД (`SERIAL`/автоинкремент), уникально,
   неизменяемо после создания, не передаётся клиентом ни при создании, ни при правке (не входит в
   `TaskCreate`/`TaskUpdate`, только в `TaskOut`).
4. Карточка на доске вместо дедлайна показывает `TASK-{number}` тем же моноширинным шрифтом/цветом,
   что раньше был у даты.
5. Модалка создания задачи и панель деталей задачи лишаются поля «Дата», поле «Тег» переименовано в
   «Очередь» (то же место, тот же принцип ввода).
6. Существующие задачи при миграции получают номера (детерминированный порядок — по факту вставки
   строк, `SERIAL` разберётся сам), не теряют ни одного другого поля.
7. Остальной HTTP-контракт (knowledge/finance, весь набор из 64 тестов) не ломается, кроме прямо
   упомянутых полей `tag`→`queue`/убранного `due`/добавленного `number` у board-роутов.

## Осознанно не делаем

- Отдельный CRUD-экран для очередей (создание по-прежнему только «на лету» через поле карточки,
  как и с тегами сейчас) — груминг явно это исключил.
- Настраиваемый префикс ключа карточки — константа `TASK-`, не параметр настроек (в духе остального
  проекта — см. `recent_operations` в finance).
- Ручной генератор номеров в коде (по аналогии с `gen_id()`) — платформенный `SERIAL` решает то же
  самое без риска гонки при параллельных вставках.
- Хранение даты создания задачи (`created_at`) — не запрашивалось, не нужно для самого ключа
  (`SERIAL` не требует отдельной колонки с timestamp, чтобы быть автоинкрементным).

## Реализация

- Миграция 0005: `ALTER TABLE tasks ADD COLUMN number SERIAL UNIQUE`, `ALTER TABLE tasks DROP
  COLUMN due`, `ALTER TABLE tags RENAME TO queues`, `ALTER TABLE tasks RENAME COLUMN tag_key TO
  queue_key` (переименование таблицы/колонки, не пересоздание — данные и FK не теряются).
- `app/domains/board/models/`: `tag.py` → `queue.py` (класс `Queue`), `task.py` — убрать `due`,
  добавить `number: Mapped[int] = mapped_column(Integer, unique=True, init=False)` (номер выставляет
  БД, ORM его не заполняет при insert).
- `app/domains/board/dto.py`: `Tag` → `Queue`; `Task.due` убрать, добавить `Task.number: int`.
- `app/domains/board/ports.py`/`repository.py`: переименовать методы/приватные помощники
  (`_resolve_tag`→`_resolve_queue`), убрать `due` из сигнатур `create_task`/`update_task`.
- `app/api/board.py`, `app/schemas.py`: `TagOut`→`QueueOut`, `tag`/`tag_label` поля → `queue`/
  `queue_label`, `TaskCreate`/`TaskUpdate` без `due`, `TaskOut.number: int`.
- `static/index.html`: убрать поле «Дата» из модалки и панели деталей; `input-tag`/`tag-options` →
  `input-queue`/`queue-options`, label «Тег» → «Очередь».
- `static/app.js`: `TAGS`/`getTag`/`.tag` → `QUEUES`/`getQueue`/`.queue`; карточка рендерит
  `TASK-{task.number}` вместо `task.due`.
- `static/style.css`: класс `.due` → `.task-key` (та же моноширинная стилистика), `.tag` → `.queue`.
