# 0015 — Очереди как фильтр видимости, а не просто ярлык

**Статус:** done

## Контекст

Продолжение TRACKER-6 (`specs/0014-queues-and-card-key.md`). После реализации 0014 пользователь
указал на смысловую ошибку: очереди были сделаны как переименованный тег — необязательная метка,
задачи всех очередей видны на доске одновременно. Это противоречит самому смыслу очередей (в духе
Jira) — задачи из разных очередей **не должны быть видны одновременно**, иначе очередь ничем не
отличается от тега. PR по 0014 (#7) ещё не смёржен — правки вносятся той же веткой/тем же тикетом,
а не отдельным follow-up.

## Груминг (зафиксировано в диалоге)

1. Активная очередь выбирается **селектором/вкладками над доской** — по аналогии с тем, как уже
   устроены вкладки «Доска»/«База знаний»/«Финансы» в шапке, только для очередей внутри самой доски.
   Доска показывает задачи **только** выбранной очереди во всех статусах разом; переключение вкладки
   меняет весь набор видимых карточек.
2. Очередь у задачи обязательна — **создание задачи без очереди запрещено**. Раз доска всегда
   отфильтрована по одной очереди, задача без очереди была бы невидима ни в одном фильтре — значит,
   такое состояние не должно быть достижимо в принципе, а не просто визуально скрыто.

## Критерии приёмки

1. `POST /api/tasks` требует непустой `queue` — пустая строка/отсутствие поля → 400
   (`title is required`-подобная проверка на уровне роута, без обращения к домену). `PATCH
   /api/tasks/{id}` не даёт снять очередь (`queue: null`/`""`) с существующей задачи — 400.
2. Миграция 0006: у уже существующих задач с `queue_key IS NULL` (созданы до этого тикета — тестовый
   хелпер `seed_status` создавал такие) простановка очереди — задачи получают одну и ту же служебную
   очередь-заглушку `общее`/`general`, создаваемую самой миграцией, а не удаляются и не блокируют
   апгрейд. Так после миграции инвариант «у каждой задачи есть очередь» верен для всех старых строк,
   без ручного разбора вручную.
3. Доска (`static/app.js`/`index.html`) получает переключатель очередей над `.board` (список
   существующих очередей в виде вкладок/пилюль, тот же визуальный паттерн `.range-btn`, что уже
   используется в «Финансах»/«Базе знаний» для похожих переключателей). Выбор сохраняется в
   `localStorage` (по аналогии с `boardAlign`) и восстанавливается при следующем визите; если
   сохранённой очереди больше не существует — выбирается первая из списка.
4. `render()` фильтрует `tasks` по активной очереди **до** разбивки по статусам — в каждой колонке
   виден только срез текущей очереди, а не все задачи всех очередей.
5. Так как весь борд теперь всегда одной очереди, метка-«таблетка» очереди на самой карточке (то, что
   было `.queue`-чипом) убирается — она была нужна ровно чтобы отличать очереди друг от друга при
   одновременной видимости, чего теперь не бывает. Модалка создания и панель деталей задачи
   сохраняют поле «Очередь» (для смены/выбора при создании), но оно обязательное, не может быть
   пустым.
6. Если очередей ещё нет вообще (совсем пустая доска, до первой созданной задачи) — переключатель не
   рендерится, показывается тот же формат приглашения создать первую задачу, что и сейчас у пустой
   доски; создание первой задачи обязано указать название новой очереди (валидация из п.1 работает
   одинаково и здесь).

## Осознанно не делаем

- Режим «показать все очереди сразу» — явно противоречит смыслу фичи по словам пользователя, не
  добавляем даже как опцию.
- Отдельная колонка/фильтр очереди на каждый статус (второй вариант, который предлагался и был
  отклонён) — выбран единый переключатель над всей доской.
- Массовый перенос задач между очередями одним действием — вне рамок этого тикета, каждая задача
  переносится по отдельности через существующее поле «Очередь» в панели деталей.

## Реализация

- `app/api/board.py`: валидация непустого `queue` в `create_task`/`update_task` по аналогии с уже
  существующей проверкой `title`.
- Миграция 0006: `INSERT INTO queues (...) VALUES ('general', 'общее', ...)` (если ещё нет),
  `UPDATE tasks SET queue_key = 'general' WHERE queue_key IS NULL`.
- `static/index.html`: `#queue-switcher` — контейнер вкладок над `.board`, по образцу
  `#finance-range-control`.
- `static/app.js`: `activeQueue` state (+ `getBoardActiveQueue`/`setBoardActiveQueue` пара, зеркалит
  `getAlign`/`applyAlign`), `render()` фильтрует по нему, `renderQueueSwitcher()` рисует вкладки.
  Убрать `.queue`-чип из разметки карточки (`card.innerHTML` в `render()`).
- `static/style.css`: `.queue`-чип-стили можно оставить (переиспользуются переключателем вкладок) или
  убрать, если не нужны — уточняется по ходу реализации.
