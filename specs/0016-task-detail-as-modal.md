# 0016 — Открытие карточки формой вместо отдельной страницы

**Статус:** draft

## Контекст

TRACKER-10 (из БД приложения). Сейчас открытие задачи — переход по `#/task/{id}`,
`handleRoute()` прячет шапку и доску, показывает `#detail-view` на весь экран (`static/app.js:1347-1383`,
`static/index.html:183-191`). Хотим вместо отдельного полноэкранного вида — оверлей-форму поверх доски,
как у остальных модалок (`#overlay`, `#topic-overlay` и т.п., `static/style.css:654-674`), с плавной
анимацией появления.

## Груминг

1. Хэш-роутинг для задачи (`#/task/{id}`) сохраняется — прямая ссылка на задачу и `Esc`/кнопка "назад"
   должны продолжать работать, меняется только визуальное представление (оверлей вместо full-page).
2. Анимация — вход/выход как у остальных оверлеев в проекте, но с более выраженным эффектом (сейчас
   `.overlay` просто `display: none/flex` без transition) — добавляем fade+scale по аналогии с
   `card-in` (`static/style.css:366-375`), на закрытие симметрично.
3. Все текущие поля и поведение детальной карточки (заголовок, ключ `TASK-{number}`, очередь, статус,
   описание, удаление, автосохранение по `change`) переносятся как есть — меняется только контейнер и
   способ показа/скрытия.

## Критерии приёмки

1. Клик по карточке на доске открывает оверлей-модалку с формой задачи поверх доски (доска остаётся
   видна под затемнением), без перехода на отдельный экран/скрытия шапки.
2. URL при открытии меняется на `#/task/{id}` (как сейчас), прямой переход по такой ссылке или
   обновление страницы с этим хэшем в адресной строке сразу открывает модалку поверх доски.
3. Закрытие — по клику на затемнение, по `Esc` (через существующий `MODAL_CLOSERS`, `static/app.js:420`),
   по кнопке закрытия в самой форме — возвращает `location.hash = ''` и скрывает модалку.
4. Появление и закрытие модалки анимированы (fade + лёгкий scale/translate), не мгновенный
   `display: none ↔ flex`.
5. Содержимое формы (заголовок, `TASK-{number}`, поля «Очередь»/«Статус», описание, кнопка «Удалить
   задачу», подсказка «Сохранено») и вся логика сохранения/удаления не меняются.
6. Остальные оверлеи (`#overlay`, `#topic-overlay`, `#concept-overlay`, `#block-overlay`) и их поведение
   не затрагиваются.

## Осознанно не делаем

- Не меняем хэш-роутинг как механизм (остаётся `#/task/{id}`) — просто рендерим по этому хэшу оверлей
  вместо full-page вида, чтобы не трогать deep-linking и историю браузера.
- Не добавляем отдельную библиотеку анимаций — используем CSS transition/keyframes, как весь остальной
  проект.
- Не меняем состав полей формы и API-контракт — только контейнер/способ показа.

## Реализация

- `static/index.html`: `#detail-view` (`<section>` с `.back-link` и `.detail-card`) превращается в
  оверлей `<div class="overlay" id="detail-overlay"><div class="modal detail-modal" id="detail-card">
  ...</div></div>` — по аналогии с `#overlay`/`#topic-overlay`. Кнопка «Назад к доске» → кнопка-крестик
  закрытия внутри модалки (`onclick="goToBoard()"`), затемнение кликабельно для закрытия.
- `static/app.js`:
  - `handleRoute()` (`static/app.js:1347-1383`) — вместо `appHeader.classList.add('hidden')` +
    `detailView.classList.remove('hidden')` полноэкранного вида: показываем доску как обычно (шапка не
    прячется) и добавляем `detail-overlay.classList.add('open')`; при отсутствии `taskMatch` — убираем
    `open`.
  - `renderDetail(taskId)` — рендерит в `#detail-card` внутри нового оверлея, содержимое не меняется.
  - `MODAL_CLOSERS` (`static/app.js:420`) — добавить `'detail-overlay': goToBoard` (Esc должен закрывать
    и эту модалку).
  - Клик по затемнению `#detail-overlay` вне `.modal` → `goToBoard()` (как у остальных оверлеев, если
    там уже есть такой паттерн — переиспользовать, иначе завести одинаковый обработчик для всех
    оверлеев).
- `static/style.css`:
  - Класс `.detail-modal` — ширина/паддинги, близкие к текущему `.detail-card` full-page (не 360px как у
    `.modal`, а шире под форму).
  - Анимация: `.overlay` получает `transition: opacity`, `.modal`/`.detail-modal` — `transition:
    transform, opacity`; `@keyframes` по аналогии с `card-in`, но для модалки (fade+scale, ~150-200ms).
  - Убрать `.back-link` стили, если после переноса они больше нигде не используются (заменяются
    крестиком закрытия в духе остальных модалок).

## Тесты

Это фронтенд-фича без изменений HTTP-контракта — `tests/api/*` не меняются. Ручная проверка (описать в
PR/чек-листе, автотестов для UI в проекте нет): открытие карточки кликом и по прямой ссылке
`#/task/{id}`, закрытие по крестику/клику вне модалки/`Esc`, сохранение полей и удаление задачи из
модалки работают как раньше.
