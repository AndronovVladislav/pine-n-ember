# 0019 — Операции выбранной категории в финансах

**Статус:** draft

## Контекст

TRACKER-13 (из базы приложения): на дашборде «Финансов» категории показывают только итоговую сумму за выбранный
период. Пользователь не может
перейти к отдельному списку и проверить, из каких операций сложилась эта сумма. Блок «Последние операции» не
решает задачу: он ограничен десятью записями и смешивает все категории. У расхода также нет пояснения: по дате и
сумме не всегда понятно, что именно было оплачено.

## Критерии приёмки

1. Нажатие на строку категории расходов или доходов открывает отдельную страницу с операциями этой категории за
   текущий выбранный период. У страницы есть ссылка назад к дашборду «Финансов».
2. Страница показывает дату, исходную сумму и валюту каждой операции. Для расходов сумма показана со знаком «−»,
   для доходов — со знаком «+».
3. У расхода есть необязательное текстовое описание. При создании расхода пользователь может заполнить его в поле
   «Описание». На странице операций непустое описание показано рядом с датой.
4. `GET /api/finance/categories/{category_id}/operations?date_from=&date_to=` возвращает все операции категории в
   пределах включительного диапазона дат, от новых к старым, вместе с описанием каждой операции. Обе границы
   периода обязательны.
5. Запрос к несуществующей категории возвращает 404. Если в периоде нет операций, API возвращает пустой список, а
   страница показывает понятное пустое состояние.
6. Существующие маршруты и ответ дашборда не меняются.

## Осознанно не делаем

- Редактирование и удаление операций со страницы — текущая задача только показывает состав категории.
- Описание для доходов: оно не запрошено, поэтому поле хранится только у расходов.
- Пагинацию: список ограничен одной категорией и выбранным пользователем периодом; добавим её отдельной задачей,
  если операций станет много.
- Изменение расчёта сумм на дашборде: панель использует те же сохранённые операции, а не пересчитывает итог.

## Реализация

- Миграция добавляет nullable-колонку `description` в `operations`; значения существующих расходов и доходов —
  `NULL`.
- `Operation`, DTO и схемы API получают `description: str | None`. Создание расхода сохраняет переданное описание;
  создание дохода всегда сохраняет `NULL`.
- `FinanceRepository` и `SqlAlchemyFinanceRepository` читают операции одной категории за диапазон дат. Сначала
  проверяют существование категории, затем выбирают операции с сортировкой по дате от новых к старым.
- `app/api/finance.py` отдаёт операции через `GET /finance/categories/{category_id}/operations`.
- `static/app.js`: строка категории переходит по адресу `#/finance/categories/{category_id}`. Роут показывает
  отдельную страницу и возвращает на дашборд по ссылке «Назад к финансам».
- `static/index.html` и `static/style.css`: добавить поле «Описание» для расхода, страницу операций и пустое
  состояние в стиле существующих блоков финансов.

## Тесты

`tests/api/test_finance.py`: операции одной категории возвращаются полностью, включая описание расхода, без
операций другой категории и за пределами периода, в порядке от новой даты к старой; несуществующая категория
возвращает 404.
